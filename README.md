# pars-bot — автопостинг с рерайтом и продвижением

Юзербот на Python (Kurigram — поддерживаемый форк Pyrogram) от лица обычного аккаунта Telegram:
ловит посты с картинками из каналов-доноров → переписывает текст через нейросеть MiniMax
→ публикует в нужном канале, не скачивая картинки → пересылает готовый пост промо-боту.

Список доноров и адрес канала правятся **кнопками в твоём боте** (`@bot_post_sam_bot`) — без кода, без переменных окружения и без ручных сообщений в группе.

## Как это работает

1. Форум-группа с включёнными «Темами» — это хранилище списка. Создаётся кнопкой «🏛 Создать группу», писать её руками не нужно. Каждая тема = категория (например «Спорт»), пишет в неё бот по кнопкам.
2. **Название темы = название твоего канала.** Бот находит канал с таким же названием и понимает, куда публиковать. Если канал называется иначе, напиши его юзернейм в название темы: `Спорт @sport_channel`.
3. Ссылки внутри темы (`@donor_channel` или `https://t.me/donor`, можно несколько в одном сообщении) = доноры этой категории.
4. Новый пост с фото из донора → подпись уходит в API MiniMax (модель `AI_MODEL`); промпт просит переписать вовлекающе и убрать ссылки, @юзернеймы и упоминания авторов.
5. Картинка публикуется по своему `file_id` (файл никуда не качается, место на диске не тратится).
6. Альбомы: `media_group_id` кэшируется, карточки собираются через `get_media_group`, рерайт делается один раз, публикация — одним постом через `send_media_group` (новый текст на первой карточке).
7. Опубликованный пост уходит промо-боту по шагам его диалога: нажатие кнопки «Просмотры» → пересылка поста → отправка числа просмотров; ответ бота попадает в журнал.
8. Тот же пост встаёт в очередь на бесплатные реакции (smmnakrutka.ru): бот ждёт пять минут, получает у сервиса разрешение и отправляет ссылку на пост в их форму — ровно так, как это делает человек на странице. Заказов не больше одного в час, очередь держит не больше шести постов.
9. Ошибки ИИ (500/502/таймаут): `AI_RETRIES` попыток с паузой `AI_RETRY_DELAY`, затем публикация оригинального текста. Отказ ключа или пустой баланс MiniMax (HTTP 401/402/403) — без повторов: сразу публикуем оригинал и пишем в журнал, что нужен рабочий ключ или пополнение счёта. `FloodWait` — автоматическая пауза на столько секунд, сколько просит Telegram. Скрипт не падает.

## Шаг 0. Кнопки управления в твоём боте

Открой своего бота (`@bot_post_sam_bot`) и нажми `/start` — дальше всё кнопками:

| Кнопка | Что делает |
| --- | --- |
| «📂 Каналы и доноры» | список каналов-категорий, у каждого число доноров |
| «🏛 Создать группу» | написать название — бот создаст форум-группу-хранилище, ты в ней владелец |
| «➕ Новый канал» | написать название своего канала — тема в группе создаётся сама |
| «➕ Донор» | прислать `@юзернейм` или `https://t.me/...` (можно несколько ссылок сразу) |
| «🗑 имя донора» | убрать донора: вычеркнуть из списка и удалить сообщение в теме |
| «✏️ Переименовать» | сменить название категории (и, если нужно, канал, куда постить: `Название @username`) |
| «🗑 Убрать канал целиком» | удалить тему категории и всех её доноров; бот сначала спросит подтверждение |
| «✏️ Переименовать склад» | сменить название группы-хранилища (темы и доноры не меняются) |
| «🔄 Обновить список» | перечитать все темы группы заново |
| «⏸ Пауза» / «▶ Пуск» | ловить посты, но не публиковать / возобновить |
| «🎭 Реакции» | включить или выключить бесплатную накрутку реакций на новые посты |
| «ℹ️ Статус» | группа, промо, реакции, нейросеть, поймано/опубликовано/в промо/сбоев |

Бот работает в одном процессе с юзерботом и действует через него: группы он не видит, но может писать в темы и удалять сообщения. Если группу создаёт кнопка «🏛 Создать группу», её владельцем становится сам аккаунт-юзербот — права настраивать не нужно. Готовую чужую группу стоит сделать так, чтобы аккаунт мог управлять темами и удалять сообщения. В чате не появляется служебных сообщений, только ответы на кнопки.

Кнопки слышат только владельца аккаунта из `SESSION_STRING` (и id, вписанные в `PANEL_ADMINS`). Если `BOT_TOKEN` не задан, панель молчит — тогда остаётся запасной способ ниже.

Частые перезапуски злят Telegram: вход бота панели может упереться в `FLOOD_WAIT` (иногда ~30 минут). Бот ждёт эту паузу сам и не перезапускается — повторный вход только удлиняет бан. Всё это время автопостинг работает как обычно, просто кнопки временно не отвечают.

## Команды в группе управления (запасной способ)

| Команда | Что делает |
| --- | --- |
| `/список` | текущие темы, каналы и доноры |
| `/обнови` | перечитать все темы заново (после добавления или удаления ссылок) |
| `/статус` | тем, доноров, поймано/опубликовано/переслано, последняя публикация, замечания |
| `/пауза` | ловить посты, но не публиковать |
| `/старт` | возобновить публикацию |
| `/убери` | (ответом на сообщение со ссылкой) вычеркнуть донора и удалить это сообщение |
| `/помощь` | короткая инструкция |

Команды и ссылки принимает только владелец группы или её админ. Ссылки, добавленные в General-тему, не работают — тема должна называться как канал.

## Шаг 1. Данные приложения Telegram

Зайди на https://my.telegram.org под тем аккаунтом, который будет ботом → **API development tools** → получи `API_ID` и `API_HASH`.

Аккаунт должен: состоять во всех каналах-донорах, быть **админом** целевых каналов с правом публикации и состоять в группе управления.

## Шаг 2. Строковая сессия

```
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python make_session.py --window
```

Откроется отдельное окно: там ввести номер (`+7...`), затем код из уведомления Telegram (и облачный пароль, если он есть). Строка `SESSION_STRING` сохранится в `.env` автоматически — копировать и присылать её никуда не нужно. Если Telegram долго не даёт код, есть вход по QR: `python make_session.py --window --qr` (сканируешь тем же телефоном: Настройки → Конфиденциальность → Активные сеансы → Сканировать QR-код).

Ключ управляющего бота из `@BotFather` вводится в таком же окне и тоже сохраняется сам:

```
python make_session.py --window --token
```

Kurigram ставится вместо Pyrogram (это тот же импорт `pyrogram`), поэтому проект держат в отдельном окружении: другие боты на старом Pyrogram останутся нетронутыми.

## Шаг 3. Настройки

```
copy .env.example .env
```

Заполни `.env` по комментариям внутри. Минимум: `API_ID`, `API_HASH`, `SESSION_STRING`, `BOT_TOKEN`, `MINIMAX_API_KEY`, `PROMO_BOT`.
`MANAGEMENT_CHAT` можно оставить пустым: группа-хранилище нигде не записана, бот после перезапуска сам находит её среди чатов - свою группу он опознаёт по тому, что аккаунт в ней владелец. Если таких групп несколько, бот напишет их список с числовыми id в лог, и id нужной можно вписать сюда.

Продвижение — это диалог с ботом Lucky Up (https://t.me/LuckyUpbot), бот повторяет его шаги за тебя:

| Шаг | Настройка | Что делает бот |
| --- | --- | --- |
| 1 | `PROMO_BUTTON=Просмотры` | находит в диалоге с ботом кнопку с таким словом (её эмодзи не важны) и нажимает — бот отвечает «Перешли нужный пост в бот». Кнопку с адресом (обычную, не скрытую) бот «нажимает» так же, как это делает Telegram: отправляет её надпись своим сообщением. Скрытую (callback) кнопку жмёт по-настоящему |
| 2 | — | пересылает опубликованный пост в `PROMO_BOT` |
| 3 | `PROMO_VIEWS=4100` | отправляет число — это **сколько просмотров добавить** к посту, а не сколько должно получиться |
| 4 | — | читает ответ бота и пишет его в журнал: «Готово!» или отказ |

Между шагами пауза `PROMO_DELAY` сек. `PROMO_BUTTON` пусто — кнопку не жмёт, `PROMO_VIEWS=0` — число не отправляет (тогда остаётся только пересылка).

Реакции — это бесплатная форма на https://smmnakrutka.ru/free-telegram-reactions (там же можно бесплатно накрутить подписчиков и просмотры, но бот по умолчанию заказывает только реакции). Правила сервиса: старт 0-15 минут, один заказ в час, ВСЕ реакции должны быть разрешены в настройках канала, ссылка — только на пост публичного канала. Бот повторяет те же шаги человека на странице: берёт ссылку `https://t.me/канал/номер?single`, ждёт пять минут, спрашивает у сервиса разрешение и только потом отправляет заказ с ним. Без разрешения заказ не уходит: в журнале появится «Реакции: заказ ... не отправился», а публикация пойдёт как обычно.

| Настройка | Что делает |
| --- | --- |
| `REACTIONS=0` | совсем выключить реакции (кнопка «🎭 Реакции» переключает это на ходу) |
| `REACTIONS_INTERVAL=3600` | сколько секунд держать между заказами — по часам сервиса |
| `REACTIONS_EMAIL=` | почту, если хочешь, чтобы сервис присылал уведомление (поле необязательное) |
| `REACTIONS_TIMEOUT=30` | сколько секунд ждать ответа сервиса |

Проверка локально: `python selftest.py` (163 проверки на фейковом клиенте, Telegram не трогает), затем `python main.py` — должны появиться строки «Вход выполнен», «Панель управления: …», «Группа управления: …», «Готов - жду новые посты от доноров».

## Шаг 4. Railway

1. Залей этот проект в репозиторий `pars-bot` на GitHub.
2. Railway → New Project → **Deploy from GitHub repo** → выбери `pars-bot` (сервис соберётся сам, `railway.json` и `requirements.txt` уже настроены).
3. В сервисе: **Variables** → добавь значения из `.env` (строго теми же именами; `SESSION_STRING` и `BOT_TOKEN` целиком, без кавычек). Старые `SOURCE_CHATS` и `TARGET_CHAT` больше не нужны — их можно удалить.
4. Deploy → **Deploy Logs**: статусы идут цепочкой «Пойман пост → Рерайт завершён → Опубликовано → Переслано в промо-бота».

Если пуш в GitHub перестал собирать деплой, привязку можно вернуть из консоли, без дашборда:

```
railway service source connect --repo vitya55519-alt/pars-bot --branch main --service pars-bot
```

Проверка: `railway deployment list` — у самого свежего деплоя должен быть `commitHash` последнего коммита.

`.session`-файлы не используются — Railway их затирает, поэтому вход только по `SESSION_STRING`. Список доноров после перезапуска собирается заново из группы, ничего терять не нужно.

## Стоимость и лимиты

- Тариф MiniMax смотри в своей консоли platform.minimax.io (блок про баланс/биллинг): оплата за входные и выходные токены, на один пост уходит порядка 1-2 тыс. токенов.
- У MiniMax нельзя полностью отключить «размышление» модели, оно тоже списывается из выходных токенов и задерживает ответ, поэтому стоит `AI_REASONING_EFFORT=low`. Для экономии можно поставить `AI_MODEL=MiniMax-M3.1-Flash`.
- Подпись картинки в Telegram — максимум 1024 символа: длинный ответ ИИ обрезается по слову.
- Альбом — максимум 10 карточек, лишние отбрасываются.
- Темы бывают только в группе с включённым «Темы»; в канале тем нет. При сборке списка из каждой темы читается до `HISTORY_LIMIT` сообщений (по умолчанию 200).

## Что учесть (честные ограничения)

- Репосты и накрутка просмотров — то, за что Telegram банит аккаунты и ограничивает каналы. Для бота нужен отдельный НЕ основной аккаунт, а промо-бот — это отдельные платежи на его стороне.
- Бесплатные реакции — чужой сервис: он может в любой момент поменять правила, задержать заказ или перестать отвечать. Бот не ругается и не падает, но и гарантий не даёт: смотри строки «Реакции:» в журнале и в «ℹ️ Статус».
- Доноры с включённым запретом копирования («защищённый контент») не отдадут картинку — такие посты бот пропустит и напишет в лог.
- В целевом канале **нельзя** включать «Запрет копирования» (Restrict saving content), иначе пересылка в промо-бота не пройдёт.
- Кэш альбомов живёт в памяти: после перезапуска Railway бот может заново обработать альбом, прилетевший в момент перезапуска.
- Название темы и название канала сверяются без учёта регистра и эмодзи. Если совпадения нет — бот напишет об этом в логах и в `/статус`, а пока можно явно указать канал в названии темы.
- Тема «General» (первая) в расчёте не участвует: там ссылки не разбираются.
