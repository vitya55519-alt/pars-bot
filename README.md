# pars-bot — автопостинг с рерайтом и продвижением

Юзербот на Python (Pyrogram) от лица обычного аккаунта Telegram:
ловит посты с картинками из каналов-доноров → переписывает текст через нейросеть MiniMax
→ публикует в твоём канале, не скачивая картинки → пересылает готовый пост промо-боту.

## Как это работает

1. Новое сообщение из `SOURCE_CHATS`, только с фотографией.
2. Подпись уходит в API MiniMax (модель `AI_MODEL`), промпт просит переписать пост вовлекающе и убрать ссылки, @юзернеймы и упоминания авторов.
3. Картинка публикуется по своему `file_id` (файл никуда не качается, место на диске не тратится).
4. Альбомы: `media_group_id` кэшируется, карточки собираются через `get_media_group`, рерайт делается один раз, публикация — одним постом через `send_media_group` (новый текст на первой карточке).
5. Опубликованный пост пересылается в `PROMO_BOT`; при необходимости боту отправляется команда или нажимается его inline-кнопка.
6. Ошибки ИИ (500/502/таймаут): `AI_RETRIES` попыток с паузой `AI_RETRY_DELAY`, затем публикация оригинального текста. `FloodWait` — автоматическая пауза на столько секунд, сколько просит Telegram. Скрипт не падает.

## Шаг 1. Данные приложения Telegram

Зайди на https://my.telegram.org под тем аккаунтом, который будет ботом → **API development tools** → получи `API_ID` и `API_HASH`.

Аккаунт должен: состоять во всех каналах-донорах и быть **админом** целевого канала с правом публикации.

## Шаг 2. Строковая сессия

```
pip install -r requirements.txt
python make_session.py --window
```

Откроется отдельное окно: там ввести номер (`+7...`), затем код из уведомления Telegram (и облачный пароль, если он есть). Строка `SESSION_STRING` сохранится в `.env` автоматически — копировать и присылать её никуда не нужно.

## Шаг 3. Настройки

```
copy .env.example .env
```

Заполни `.env` по комментариям внутри. Минимум: `API_ID`, `API_HASH`, `SESSION_STRING`, `MINIMAX_API_KEY`, `SOURCE_CHATS`, `TARGET_CHAT`, `PROMO_BOT`.

Промо-бот включается одним из режимов:

| PROMO_MODE | Что делает после пересылки |
| --- | --- |
| `forward` | только пересылает пост в бота (по умолчанию) |
| `command` | через `PROMO_DELAY` сек. отправляет боту текст из `PROMO_COMMAND` |
| `button` | через `PROMO_DELAY` сек. сам нажимает кнопку в диалоге с ботом, в тексте которой есть слово из `PROMO_BUTTON` |

Проверка локально: `python main.py` — должны появиться строки «Вход выполнен», «Целевой канал доступен», «Готов - жду новые посты от доноров».

## Шаг 4. Railway

1. Залей этот проект в репозиторий `pars-bot` на GitHub.
2. Railway → New Project → **Deploy from GitHub repo** → выбери `pars-bot` (сервис соберётся сам, `railway.json` и `requirements.txt` уже настроены).
3. В сервисе: **Variables** → добавь значения из `.env` (строго теми же именами; `SESSION_STRING` целиком, без кавычек).
4. Deploy → **Deploy Logs**: статусы идут цепочкой «Пойман пост → Рерайт завершён → Опубликовано → Переслано в промо-бота».

`.session`-файлы не используются — Railway их затирает, поэтому вход только по `SESSION_STRING`.

## Стоимость и лимиты

- Тариф MiniMax смотри в своей консоли platform.minimax.io (блок про баланс/биллинг): оплата за входные и выходные токены, на один пост уходит порядка 1-2 тыс. токенов.
- У MiniMax нельзя полностью отключить «размышление» модели, оно тоже списывается из выходных токенов и задерживает ответ, поэтому стоит `AI_REASONING_EFFORT=low`. Для экономии можно поставить `AI_MODEL=MiniMax-M3.1-Flash`.
- Подпись картинки в Telegram — максимум 1024 символа: длинный ответ ИИ обрезается по слову.
- Альбом — максимум 10 карточек, лишние отбрасываются.

## Что учесть (честные ограничения)

- Репосты и накрутка просмотров — то, за что Telegram банит аккаунты и ограничивает каналы. Для бота нужен отдельный НЕ основной аккаунт, а промо-бот — это отдельные платежи на его стороне.
- Доноры с включённым запретом копирования («защищённый контент») не отдадут картинку — такие посты бот пропустит и напишет в лог.
- В целевом канале **нельзя** включать «Запрет копирования» (Restrict saving content), иначе пересылка в промо-бота не пройдёт.
- Кэш альбомов живёт в памяти: после перезапуска Railway бот может заново обработать альбом, прилетевший в момент перезапуска.
